`mw go <query>` is forgiving: you don't need to type the exact catalog name.
A multi-signal resolver scores every project and branch in the catalog and
picks the best match.

## The four signals

| Signal     | Default weight | What it measures                                          |
|------------|----------------|-----------------------------------------------------------|
| `fuzzy`    | 0.35           | Normalized Levenshtein with prefix and substring bonuses  |
| `frecency` | 0.35           | Visit frequency × time-decay (zoxide-style)               |
| `activity` | 0.15           | Recent commit activity (reserved for upcoming features)   |
| `context`  | 0.15           | How close the candidate is to your current directory      |

The composite score is the weighted sum. Tweak the weights via the
`resolver` table in `config.toml`:

```toml
[config.resolver]
weight_fuzzy = 0.4
weight_frecency = 0.4
weight_activity = 0.05
weight_context = 0.15
```

## Fuzzy matching

The fuzzy score normalizes the edit distance between your query and the
candidate name, then applies bonuses:

- Exact match → 1.0
- Prefix match → 1.3× multiplier
- Substring match → +0.2 bonus
- Capped at 0.95 for non-exact matches so an exact name always wins ties

## Frecency

Every successful `mw go` records a visit to the `repo:branch` key in
`$XDG_STATE_HOME/makework/visits.json`. The score for each candidate is
`visit_count × time_weight`, where `time_weight` decays over roughly an hour
of inactivity. Sibling branches of a heavily-visited repo also get a partial
boost.

The shell hook from `mw init <shell>` records visits on every `cd`, not just
through `mw go` — so any time you wander into a known repo, the resolver
notices.

## Disambiguation

If the top two candidates score within 10% of each other, `mw go` refuses to
guess and prints both:

```
Multiple matches for 'auth':
  1. auth-service (main)
  2. backend (auth-rewrite)
Use repo@branch syntax for precise routing.
```

To bypass the resolver entirely, use the explicit form:

```sh
mw go auth-service@main
```

## Inspecting scores

`mw resolver explain <query>` prints the per-signal breakdown for the top
candidates. Use it to debug why a query routes to a surprising target or to
tune your weights.

```sh
$ mw resolver explain auth
Query: 'auth'
Weights: fuzzy=0.35 frecency=0.35 activity=0.15 context=0.15

REPO                 BRANCH       FUZZY    FREC    ACT    CTX     TOTAL
auth-service         main         0.950   0.812  0.000  0.500   0.692
backend              auth-rewrite 0.620   0.450  0.000  0.500   0.449
```

## See all matches

`mw go <query> --list` shows the top 10 candidates with scores instead of
navigating, which is handy for piping into other tools.
